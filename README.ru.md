# Beam402

**Открытая система хронометража для драг-рейсинга** — лучи стейджинга,
ёлка, замер ET / 60ft / скорости на ловушке и судейский софт. Собирается из
промышленных компонентов, доступных в любом регионе, — чтобы любой клуб мог
провести настоящий этап без импортного «чёрного ящика» за цену мотора.

> **Статус: прототип, неделя 1.** Пока ничего не работает. Архитектура
> спроектирована, компоненты заказаны, впереди стендовая валидация.
> Следите за коммитами.

*Break the beam.*

## Зачем

Проект родился в день, когда национальный этап по драгу отменили посреди
финалов: единственная в стране судейская система отказала, а второй не
существовало. Хронометраж оказался единой точкой отказа для целой гоночной
сцены. Коммерческие системы есть — но стоят как постройка мотора, едут
месяцами и обслуживаются за океаном.

Beam402 — ответ на это: открытая, воспроизводимая, ремонтопригодная в поле
система для низового драг-рейсинга — тренировочных дней, джуниорских этапов,
альтернативных лиг и всего, до чего большие системы никогда не доедут.

## Что внутри

- **Узлы-таймеры** — одинаковые коробки вдоль трассы (старт, 60ft, 1/8,
  финиш), фиксирующие разрыв лучей с разрешением ≤1 мс
- **Промышленные фотодатчики «на просвет»** — паспортный отклик 1 мс, IP67 и
  запас по дальности, чтобы держать дым от прожига; не хобби-модули
- **Проводная магистраль RS-485** с широковещательным старт-импульсом — без
  синхронизации часов, без радио-джиттера, проверяется осциллографом
- **Модуль ёлки** — полная логика стейджинга, AutoStart, standard и pro tree
- **Судейский софт** — классы, квалификация, сетки, тайм-слипы и локальное
  веб-табло для зрителей
- **Автономное питание узлов** — перебитый кабель теряет данные, но не узлы

Приоритеты дизайна по порядку: доверие к цифрам, ремонт в поле силами
неспециалиста, низкая стоимость, поэтапное развёртывание (старт + финиш +
ёлка — уже полноценная рабочая система).

## Дорожная карта

- [ ] **Стендовая валидация** — джиттер датчиков (в разности с опорным
      детектором), асимметрия краёв перекрытия и восстановления, температурный
      дрейф, точность аппаратного захвата, помехозащищённость старт-импульса
      на полной длине кабеля *(от этого зависит всё остальное)*
- [x] Проектирование софта — архитектура, карта регистров шины, формат
      mapping-файла
- [x] Контракт шины в виде кода — крейт карты регистров, документы
      генерируются из него и сверяются с ним
- [x] Скрипт редукции стендовых данных — [`bench/`](bench): VCD на входе,
      распределение на выходе
- [x] Mapping-файл: валидация при загрузке
- [x] Симулятор узла и ёлки, опрос шины, судейская логика поверх него — ET,
      промежуточные, скорость в ловушке, реакция, гандикап и breakout
- [x] Слипы: `beam402 sim scenarios/bracket.toml --format bracket
      --dial 12.34,7.50` печатает полный заезд на симуляторе
- [x] Запись и воспроизведение сессии — `--record` пишет каждую транзакцию шины,
      `beam402 replay` прогоняет её тем же кодом и печатает тот же слип
- [x] `beam402 scope` — одна самодостаточная страница: трасса, ёлка, лучи, шина
      и события на прокручиваемой шкале времени
- [x] Зрительское табло как пиксельный кадр объявленного разрешения (**D29**):
      страница — превью панели, а не второй, несогласованный с ней дизайн
- [ ] Два узла на макетных платах (старт + финиш) + прототип ёлки
- [ ] Демо на парковке: стейджинг → ёлка → старт-импульс → ET на ноутбуке
- [ ] Несущая плата (KiCad) + заводская сборка партии
- [ ] Полевые корпуса (IP67), полная конфигурация на две полосы
- [x] Событийный слой: классы как данные, квалификация, pro- и sportsman-сетки,
      byes
- [x] Отсечка по квалификации — настройка класса, а не наша арифметика:
      `field = [8, 16]` это «топ-8 от четырёх заявленных, топ-16 от
      шестнадцати», `[16]` — фиксированное поле, не задано — едут все; плюс
      минимум для проведения класса и предел **зачётных** попыток. Не попавшие
      в поле названы поимённо: «посеян последним» и «не отквалифицировался» —
      разные фразы
- [x] HTTP-сервер, написанный а не подключённый (**D32**) — `beam402 serve`
      отдаёт заезд, табло и scope в локальную сеть без единой зависимости
- [x] Живой судейский софт (**D30**): шина на своём потоке, страница оператора
      под маркером управления и табло — всё из `beam402 serve`
- [x] Заявочные листы и день, выводимый из журнала результатов —
      `beam402 event events/club-day.toml`
- [x] Эллиминаторы по сетке — `beam402 serve --event <sheet> --log <file>`:
      пара берётся из сетки, оператор фиксирует результат, сетка продвигается.
      Машина, не вышедшая на заезд, оставляет сопернику одиночный проезд:
      едет один, зачётное время всё равно нужно, в журнал идёт победа, а не бай
- [x] Стол регистрации — `beam402 sheet entries.csv --event season.toml`
      превращает таблицу, которая у клуба уже есть, в лист заявок (**D34**)
- [x] Выгрузка дня на сервер — `beam402 push` и `beam402 host`: вживую или
      разом вечером, с возобновлением и идемпотентно (**D33**)
- [x] Контракт на чтение, на котором лига делает свой фасад — CORS на чтении,
      индекс событий и проброс их собственных id (**D35**)
- [x] Право записи на получателе — первый писатель забирает событие; `deploy/`
      — референсный способ вывести его в интернет
- [x] TLS в клиенте выгрузки — rustls за cargo-фичей, так что сборка, которая
      не уезжает с трассы, по-прежнему без зависимостей (**D36**)
- [x] Квалификация и тренировки по шине: очередь машин, а не уменьшенный
      эллиминатор — оператор вызывает машину в полосу, едут одна или две, каждый
      проезд записывается сам по себе, закрытие квалификации рисует сетку.
      Тренировочный день — это лист заявок, который никогда не разыгрывают.
      Заезд теперь сам объявляет, в каких полосах есть машины, — это же было
      нужно и баю
- [ ] Причины в журнале (**D37**): почему проиграл, аннулированный проезд,
      снятый из класса участник — чтобы регламенту, считающему фальстарты
      пилота за все круги, было что считать, а зеркалу было что сказать
- [ ] Конфигурация с ёлкой-мастером (**D31**): ёлка, два узла и телефон —
      запуск и результат каждого заезда без компьютера на трассе
- [x] Референсный получатель, реально задеплоенный, чтобы цепочка шла целиком —
      день уехал с ноутбука по TLS, отзеркалился и читается фасадом лиги через
      CORS
- [ ] Первый настоящий этап

## Участие

Проект молодой, и лучший момент повлиять на него — сейчас. Особенно нужны:
взгляд со стороны на архитектуру и журнал решений (скажите, где мы неправы —
с аргументами), опыт с фотодатчиками и RS-485 в полевых условиях, позже —
прошивка и судейский софт. Открывайте issue — можно по-русски, можно
по-английски. Правила участия и формат возражений против решений — в
[CONTRIBUTING.md](CONTRIBUTING.md) (на английском).

Живой чат — в Telegram: [t.me/beam402](https://t.me/beam402). Выводы,
влияющие на решения, возвращаются в issues — журнал проекта живёт на GitHub.

Родственные проекты: [MajicDesigns/DragLights](https://github.com/MajicDesigns/DragLights)
(логика ламп ёлки, на которой строится наш модуль) и
[RotorHazard](https://github.com/RotorHazard/RotorHazard) (открытый
хронометраж FPV-гонок — образец организации опенсорс-сообщества).
